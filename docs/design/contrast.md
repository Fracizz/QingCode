# 对比度、选择控件与文案规范（电脑版 + 手机版）

> 状态：v1（2026-11-26）。适用于 `apps/desktop/src/renderer/src/styles.css` 与 `apps/mobile/web/src/styles.css` 的 `@theme` token，以及所有组件里的颜色写法。
> 起因：手机强光下看不清对话输入框边界——输入框底 `#242424`、底栏 `#1f1f1f`、边框 `#2e2e2e`，三者两两对比度都只有 1.06–1.3:1；电脑版输入框（`#1f1f1f` 底 + `#3a3a3a` 边）同样偏弱，次要文字 `#6b6b6b` 在卡片上不到 3:1。

## 1. 硬性指标

对比度按 WCAG 2.x 相对亮度公式计算（见 §4 脚本）。“所在表面”指元素实际压在上面的那一层颜色，不是页面底色。

| 元素 | 最低对比度 | 依据 |
|---|---|---|
| 正文、标题、按钮文字（`qn-text` / `qn-prose`） | **7:1** | WCAG AAA 正文 |
| 次要文字（`qn-muted`）：副标题、时间、说明、图标按钮 | **4.5:1**，在它出现的**所有**表面上（含输入框、卡片、浮层） | WCAG AA 正文 |
| 辅助文字（`qn-dim`）：占位符、禁用、计数、kbd | **4:1**（在输入框底上）；不得承载必须读懂的信息 | 占位符要能在强光下读出 |
| **表单类输入控件外框**（输入框、搜索框、复选框）| **3:1**，与控件外侧表面相比 | WCAG 1.4.11 非文本对比 |
| 对话输入框 | 不要求外框；边界靠底色与投影区分（见 §3 第 3 条） | 它是页面上最大、位置固定的控件，不靠描边也能找到 |
| 分隔线、卡片/芯片边框（`qn-border`） | **1.4:1** | 只做分组，不承担“这里能输入”的提示 |
| 控件次级边框（`qn-border-strong`）：描边按钮、电脑版分段控件 | **1.8:1** | — |
| 手机版卡片、列表组、按钮、标签 | 不要求边框；靠底色分层（卡片 `qn-card` 压在页面底上，弹层里卡片色抬亮一档），按钮为浅填充、标签为同色 13% 浅填充 | 不是输入控件；文字本身已满足 7:1 / 4.5:1，可识别性不靠描边 |
| 焦点态 | 外框或焦点环用 `qn-outline-hover`，不得只靠底色变化 | 键盘与触屏都要看得出焦点 |

**判定口诀：表单里能输入的东西要有 3:1 的外框；只靠底色差（< 1.3:1）区分的层级在强光下等于不存在。对话输入框例外，不要为了凑指标给它加描边或边缘圈。**

### 2.1 电脑版灰色 / 浅色主题（`html[data-theme]`）

## 3. 写法约定

1. **不写裸色值**。新增颜色先进 `@theme`，组件里用 token；需要更亮的局部变体时像 `.qn-surface-float` 那样在子树里重定向 token。
2. **输入类控件一律用 `qn-outline` 外框**：电脑版 `.qn-input`、`Checkbox`、`Composer` 卡片；手机版 `.qn-input / .qn-search`（对话输入框 `.qn-composer` 除外）。不要把输入框边框写成 `qn-border` / `qn-border-strong`。
3. **对话输入框**不强制外框：手机版只用 `qn-composer` 底色加柔和投影，不加描边或边缘圈；电脑版目前保留 `qn-composer-outline` 外框，以后可按同一思路去掉。
4. **占位符**统一 `qn-dim`（手机版全局 `::placeholder`，电脑版 `placeholder:text-qn-dim`），不依赖浏览器/WebView 默认灰。
5. **层级不靠底色差单独表达**：相邻表面明暗差 < 1.3:1 时，必须再配边框或投影其中之一。
6. **改色前后都跑 §4 的脚本**，把新的组合补进 §2 表格。手机版还要在亮度拉满的真机上看一眼对话页输入框、搜索框、底部按钮。

## 4. 选择控件形态

| 场景 | 控件 | 形状 |
|---|---|---|
| 固定 2–7 项的单选（推理强度、速度、会话范围、项目排序） | **分段控件**：手机 `.qn-segment`（按钮带 `role="radio" aria-checked` 或 `aria-pressed`），电脑版 `SegmentedControl` / 模型选择器内的分段按钮 | 等宽网格。电脑端外框 8px、内项 6px，选中项用品牌色底、中性描边和加粗文字。手机端轨道四周留 4px，轨道和选中项均使用无描边的实色填充，两者至少有 1.3:1 对比度。选中项用加粗的 `qn-segment-text` 文字，焦点环单独显示。 |
| 开关型选项 | 分段控件的“关 / 开”两项，或 `Checkbox`；**不用**单个可按下的胶囊 | 同上 |
| 横向滚动的筛选、标签、已选项 | 芯片 `.qn-chip`（6px 圆角） | 高度 ≤ 32px，文字单行 |
| 带说明的列表选项（模型） | 整行卡片 `qn-row` + `rounded-lg` | 说明文字可换行（`whitespace-normal` + `overflow-wrap:anywhere`），不得溢出到右侧勾选图标 |

- **手机版分段控件共用 `.qn-segment`**。常规按钮高 40px，内圆角为按钮高度的一半，外圆角再加 4px。会话页的紧凑排序控件按钮高 28px，触控区延伸至 44px，轨道和按钮分别使用 [`ui-shell.md`](ui-shell.md) §6 的 8px 和 6px 圆角档位。
- 当前选项的说明放在分段控件下方一行 `.qn-hint`（手机）或 `Tip`（电脑），不塞进按钮里。

## 5. 文案

- 界面上的模型说明、推理强度说明一律中文：服务端 `model/list` 只给英文，统一用 `@qn/codex-client` 的 `localizeModelDescription`、`effortHint`（`packages/codex-client/src/modelText.ts`，两端共用；新增译文只改这一处）。
- 推理强度档位名用 `effortLabel`：低 / 中 / 高 / 超高 / 极高 / 极致。

## 6. 校验脚本

```js
// node contrast.mjs '#181818:#6b6b6b' '#2a2a2a:#8a8a8a'
const L = (h) => {
  const c = [1, 3, 5].map((i) => parseInt(h.slice(i, i + 2), 16) / 255)
    .map((v) => (v <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4))
  return 0.2126 * c[0] + 0.7152 * c[1] + 0.0722 * c[2]
}
for (const pair of process.argv.slice(2)) {
  const [a, b] = pair.split(':').map(L)
  console.log(pair, ((Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05)).toFixed(2))
}
```
