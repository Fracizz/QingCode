## QingCode v0.1.21-beta.7

**Language / 语言:** [English](#english) · [中文](#中文)

<a id="english"></a>

### English

A beta after v0.1.20 that makes CLI prewarming configurable per host, keeps remote prewarming from getting stuck, and polishes the mobile workbench.

#### Highlights

- Prewarming switches are now per host: a new "Local prewarming" switch plus a "Remote prewarming" switch on each connection. Turning one off stops only that host's plain-Shell and CLI prewarming, so other hosts keep their warm pools.
- Remote connections gain "Number of CLIs to prewarm at once" (1–4, default 1), saved with the connection. Opening two terminals with the same profile in a row now gets a warm CLI for both instead of cold-starting the second. Changing only the count keeps ready CLIs and trims just the extra idle ones.
- The terminal list host header shows ready/target counts from the CLI pool when CLI prewarming is on, otherwise from the plain-Shell pool. A paused pool is shown in amber, and hovering shows both pools plus the latest claim.
- Prewarming no longer stalls: a single CLI spawn has a 120-second overall limit and retries with backoff, so the pool no longer sits at "preparing" forever; the "full" badge is green and "topping up" is gray.
- A remote Server restart or a dropped event stream now retries with backoff instead of pausing the pool at `profile_exited` / `cli_not_ready`.
- Prewarming directories left non-empty by a CLI (for example Claude's `.claude`) are detected and retried automatically, so remote prewarming no longer waits at "not ready".
- Remote forced Server updates close the terminal tabs they end instead of leaving "exited" windows behind.
- The ⚡ badge now appears only when a prewarmed CLI was actually claimed, on desktop terminals, the terminal list, and the mobile session list alike. Mobile terminal titles show the badge at its intended 14px again.
- Mobile creates terminals for local projects from the local CLI pool too, matching the desktop.
- Mobile workbench silently refreshes projects and connections once when switching tabs, and the floating top-right buttons no longer look like they jitter during the tab transition.
- Mobile: the session drawer's "local" source badge is no longer clipped, and terminals attach at phone size by default while the size stays unlocked.

The matching remote Server version is `0.1.21-beta.7`.

<a id="中文"></a>

### 中文

v0.1.20 之后的测试版，把 CLI 预热改成按主机独立配置，修复远端预热的几种卡住情况，并继续打磨手机端工作台。

#### 主要变更

- 预热开关改为按主机独立管理：新增「本机预热」开关与每条远程连接的「远端预热」开关；关闭某处只停止该处的普通 Shell 与 CLI 预热，其他主机的预热池不受影响。
- 「远程连接 → 远端 CLI 预热」新增「同时预热的 CLI 数量」（1–4，默认 1），随该连接保存。连续新建两个同配置终端时，第二个也能领到已预热的 CLI，不再冷启动；只调数量时保留已就绪的 CLI，调小仅裁掉多出的空闲项。
- 终端列表的主机标题显示预热池就绪/目标数量：设了 CLI 预热的主机显示 CLI 池，否则显示普通 Shell 池；暂停时标为琥珀色，悬停可查看两个池的详情与最近领取情况。
- 预热不再卡在「准备中」：单次预热创建增加 120 秒总时限并按暂时性失败退避重试；徽标补满显示绿色、补充中为灰色。
- 远端 Server 重启或会话事件流断开时，预热按退避自动重试，不再停在 `profile_exited` 或 `cli_not_ready` 要求用户切换配置。
- 预热专用目录被 CLI 占用（例如 Claude 留下 `.claude`）时自动识别并重试，远端预热不再一直「未就绪」。
- 远程强制更新 Server 时，自动关闭因此被结束的终端标签，不再留下无用的「已退出」窗口。
- ⚡ 预热标志只在真正命中 CLI 预热时显示，电脑终端、终端列表与手机会话行统一使用同一判断；手机终端标题的闪电图标恢复 14px。
- 手机在本机项目新建 CLI 配置终端时同样先领取本机 CLI 预热，与电脑端一致。
- 手机端底部导航切页时静默刷新一次项目与连接状态；右上角浮动设置按钮不再随切页过渡的旧快照平移而像抖动。
- 手机：会话抽屉的「本机」来源标签不再被裁成半个字；尺寸未锁定时接入终端默认改用手机尺寸。

配套远端 Server 版本为 `0.1.21-beta.7`。
