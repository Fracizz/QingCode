# 离线更新远端 Server

QingCode 的安装包和便携版都不内置远端 Server（`qingcode-server`）。客户端需要从本机的离线服务包或在线下载中取得与自身版本一致的 Server，再通过 SSH 上传到远端。远端主机本身**不需要访问互联网**；本文说明客户端电脑也无法联网（或不想联网）时如何更新。

实现细节与安全约束见 [ssh-workspaces.md](./ssh-workspaces.md) 和 [direct-agent.md](./direct-agent.md)。

## 1. 获取离线服务包

从 [GitHub Releases](https://github.com/Fracizz/QingCode/releases) 或 [Gitee Releases](https://gitee.com/FrancizTest_admin/qing-code/releases) 下载与客户端**同一版本**的 `QingCode_<版本>-servers.zip`。本地打包产物为 `release/QingCode-servers.zip`。

- 版本必须与客户端一致（客户端版本见 设置 → 关于）。旧版本的服务包会被拒绝。
- 解压后得到 `servers/` 目录，内含 `manifest.json` 和各平台的二进制（如 `qingcode-server-x86_64`、`qingcode-server-aarch64`、`qingcode-server-windows-x86_64.exe`）。不要单独挑出某个文件，也不要改名；客户端按 `manifest.json` 校验大小和 SHA-256。

## 2. 放置服务包

以下任选一种，按优先级从高到低：

1. **设置里指定（推荐）**：设置 → 远程连接 → 「SSH › 服务: 离线目录」→「选择离线目录」，选中解压后的 `servers` 目录。也可从 Server 状态详情或连接管理页的「服务包来源」直接进入。
2. **环境变量**：设置 `QINGCODE_SERVER_DIR` 指向 `servers` 目录。
3. **放在程序旁边**：把 `servers/` 放到安装目录或 `QingCode.exe` 同目录。

本机文件始终优先于在线下载。完全离线时，可同时关闭「SSH › 服务: 缺失时自动下载」，避免找不到包时尝试联网。

## 3. 更新远端 Server

### 自动更新

打开受信任的项目时，如果发现远端 Server 版本与客户端不一致，客户端会在后台用本机离线包自动更新：

- 只使用版本、平台和完整性都校验通过的本机包；开启自动下载时，本机缺包才会联网获取。
- 对 Server 端口直连的连接，需要同一主机已保存、且主机指纹已确认的 SSH 连接，并能用已有凭据认证；后台不会弹出密码框。
- 每次只尝试一次，失败后不会反复重试，可以改用下面的手动更新。

### 手动更新

1. 版本不匹配时，在错误提示、Server 状态详情或连接管理页点击「更新远端服务」（Server 端口直连项目为「通过 SSH 更新远端服务」）。
2. 在更新弹窗的服务包来源中选择「使用本机离线包」，再点「选择离线目录」。选 `servers` 目录或它的父目录都可以。
3. 点「检查并准备服务包」。弹窗会显示远端需要的版本、包版本和本机来源；校验通过后再确认更新。
4. 更新会重启远端服务，可能结束其托管的终端，同一远端用户下的其他项目也可能受影响；弹窗会先请你确认影响。
5. 完成后按提示新建终端，或重试原来的操作。

在准备、上传、远端自检都成功之前，旧服务不会停止；失败时保留原程序，并尝试恢复原来的服务入口。

## 4. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| 未找到服务包 / 缺少平台文件 | 目录里没有对应远端系统和架构的二进制，或缺少 `manifest.json`。重新完整解压 zip，选择 `servers` 目录。 |
| 服务包版本过旧 | zip 版本与客户端不一致。下载与客户端同版本的 `servers.zip`。 |
| 校验失败（SHA-256 / 大小不符） | 文件损坏或被替换。重新下载并完整解压。 |
| 选了离线包仍然失败，没有改用在线下载 | 这是预期行为：「使用本机离线包」只读取所选目录，不会回退到其他目录或在线下载。需要联网获取时改选「自动获取」。 |
| 自动更新没有触发 | 检查项目是否已信任、离线目录是否指向正确版本；Server 端口直连还需要同主机且指纹已确认的 SSH 连接。之后改用手动更新。 |
| 部署后一直等不到就绪 | 常见于远端 sshd 禁止 TCP 转发。检查 `AllowTcpForwarding`，再重启远端服务或断开重连。修改离线目录或自动下载开关后会立即重试，无需重连。 |
| 内网想统一分发 | 可设置 `QINGCODE_SERVER_DOWNLOAD_BASE` 指向内网镜像，替代 GitHub 在线下载。 |
