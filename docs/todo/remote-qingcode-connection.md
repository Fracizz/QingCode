# 待做：QingCode 之间远程连接（家里连公司）

状态：待做 · 记录于 2026-11-07

## 目标

公司电脑上的 QingCode 打开一个开关，家里的 QingCode 即可连接，进行远程开发。文件、终端、Git、运行配置和 AI CLI 均在公司电脑上执行，代码、凭据与 AI CLI 登录态不落到家里。

不在范围内：
- 网络可达：默认通过公司 VPN、Tailscale 或局域网即可访问，不做内置中继或穿透。
- 镜像：不同步公司桌面已打开的终端标签和编辑器状态。
- 终端接管：不跨设备接回对方创建的终端（见下文「终端管理」）。

## 复用的现有能力

- `qingcode-server direct`：HTTPS 工作区操作与 WSS 终端/监听共用一个端口（默认 48763），见 [Server 端口直连](../direct-agent.md)。
- 安全：证书指纹固定、配对 Token、工作区信任、项目根边界、符号链接逃逸拒绝。
- 客户端：「远程连接 → 新建 Server 直连」负责导入、测试、确认指纹、保存。
- 终端：由 daemon 托管，断线不结束进程，按输出序号补发或用屏幕快照接回，见 [SSH 工作区](../ssh-workspaces.md)。
- 版本：客户端与 Server 必须完全一致，两端装同一个安装包。

## 终端管理（不改动）

- daemon 中每个 PTY 的 owner 为 `<安装 UUID>:<连接 ID>`（`src-tauri/src/remote_ssh.rs` 中的 `client_id`）；owner 不同的客户端接入时会被拒绝（`qingcode-server/src/pty.rs` 的 `attach_with`），孤儿列表也只返回本安装的终端（`daemon.rs`）。
- 因此公司和家里各自管理自己的终端，互不干扰；家里的终端在断线或重启后仍能正常接回。
- 接续 AI 对话依靠 CLI 自身的会话管理：会话文件保存在公司电脑上（`~/.claude/projects`、`~/.codex/sessions`），家里新开终端后执行 `claude --resume` / `codex resume` 即可。
- 公司遗留的终端在分离 24 小时后由 daemon 回收（常驻服务可配置），也可以在公司退出 QingCode 时选择「结束远程终端」。

## 注意事项

- 公司电脑需放行 Windows 防火墙端口，可复用现有「通过 SSH 授权放行」流程，或手动添加入站规则并限定来源。
- 公司桌面以本地方式打开项目、家里同时远程编辑时，两边会写同一批文件，依靠文件监听同步，验收需专门覆盖。
- 二期完成前只有一个配对 Token，泄露后只能重新生成，所有已配对设备需要重新配对。
- 将公司开发机暴露到外部网络前，确认符合公司安全规定，优先使用公司批准的 VPN。
