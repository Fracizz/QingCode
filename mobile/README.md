# QingCode Android

安卓版的界面与统一圆角规范见 [Android 设计规范](android/design.md)。

## APK 打包与发布

本地 `pnpm package:exe` / `pnpm package:installer` 会检查 Android 输入文件和已生成 APK 的摘要。
有更新或 APK 缺失/损坏时构建 `release/QingCode_<版本>-android.apk`，并更新 `QingCode-Android.apk`；
无更新时保留原 APK 的版本和文件。仅桌面版本号变化不触发 APK 构建。
需要 `ANDROID_HOME` / `JAVA_HOME`，也支持本项目现有 `.dev/android-build/sdk` 工具目录；
缺少工具链时提示跳过。签名沿用已有本地密钥；缓存保存在 `.dev/android-build/package-state.json`。

Release 工作流每次发布（含 beta 等预发布）都构建并上传 `QingCode_<版本>-android.apk`，Gitee 同步时一并镜像，供手机端在线更新取用。
必须配置固定发布签名密钥（`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS`，可选 `ANDROID_KEY_PASSWORD`）；
缺少密钥时工作流报错提示并跳过 APK，不阻断桌面端发布，但该版本手机无法在线更新。换签名密钥会导致手机无法覆盖安装。

## 在线更新

工作台右上角齿轮打开的「设置 → 应用更新」显示当前版本，可手动「检查更新」；默认每天自动检查一次（可关闭），发现新版本时首页显示提示卡片。
手机依次读取 GitHub、Gitee 的发布列表，选出版本号最高且附带 `QingCode_<版本>-android.apk` 的发布：beta 等预发布版本的手机也会收到更新的 beta，正式版手机只接收正式版；最新发布缺少 APK 时回退到仍比当前新的较早版本。
下载只允许 HTTPS 访问 github.com / gitee.com 发布附件及其 CDN（每次跳转都校验主机），并核对长度；安装前检查包名、versionCode 高于当前版本且签名与已安装应用一致，再通过系统 PackageInstaller 由用户确认安装。首次安装需在系统设置中允许 QingCode「安装未知应用」。可「跳过此版本」，跳过后不再提示该版本，仍可手动检查。

Android 端是终端优先的远程控制器。手机可保存多台能通过局域网访问的 Windows QingCode，在「连接」中切换、重连、重命名、修改端口、重新配对或移除。每台电脑分别提供本机、WSL 和远端已信任项目，Windows 负责 SSH、Server 连接和凭据管理。

首页「最近打开」按电脑和手机最近打开时间合并排序，最多显示 10 个当前仍受信任的项目；整页可向下滚动，底部导航固定。手机记录按电脑分别保存，重开项目移到最前，修改端口时随连接迁移，移除连接时删除。旧版电脑未提供打开时间时仅使用手机已有记录；其余项目可从「全部项目」进入。

项目列表将连接名称、IP / 主机名与路径分行显示；同名项目可按来源区分，也可搜索连接名或地址。
「WSL」筛选对应电脑直接添加的 WSL 目录；通过名为 WSL 的远端连接访问的项目归入「远端」，显示例如「远端 · WSL · localhost」。首页继续终端和终端标题也保留来源信息。

## 配对和使用

1. 在 Windows QingCode 的「设置 → 功能 → Android 移动连接」填写端口和自定义 6–20 位密码，再保存并启用。Windows 自动监听局域网 IPv4 连接（含 Tailscale 等 `100.64.0.0/10` 地址）。密码可使用纯数字、纯字母或符号，无需组合，区分大小写；默认记住，可在电脑端显示或隐藏。启用后设置页显示配对二维码；电脑有多块网卡时可切换二维码使用的地址。
2. 在 Android 的「连接」中点「添加」，选择「扫码添加」扫描电脑上的二维码，或「粘贴配对链接」粘贴电脑端「复制配对链接」得到的 `qingcode://pair?...`。系统相机或其他扫码应用打开该链接时也会直接进入配对。二维码包含地址、端口和证书指纹，手机连接时自动核对指纹，不一致会停止配对；之后只需输入密码。也可以手动填写 IPv4、端口和密码直接连接，无需手动确认指纹；首次连接会自动记住电脑证书，后续证书变化时须重新扫码或粘贴配对链接。旧版单台电脑的配对会在升级后自动导入。
3. 从「终端」继续最近使用的项目，或在「项目」中按 IP、项目名、连接名或路径搜索并打开项目。终端顶部可新建和切换会话，右上角菜单可结束会话。若列表缺少项目，在桌面添加并信任后刷新。
4. 底部命令栏支持中文输入和粘贴。常用快捷键默认只占一行，按使用频率排序：Esc、Tab、Ctrl+C、⇧Tab、↑、↓、⌫、/命令、←、→；屏幕放不下时横向滑动查看，「更多」固定在最右侧。@引用、换行、Ctrl / Alt、Home / End、翻页与符号键收在「更多」中；Ctrl / Alt 支持单次和双击锁定。横屏仍默认折叠。Tab 和 ⇧Tab 按原键发送，具体是补全还是切换模式，由终端程序决定。「终端设置 → 快捷键栏 → 调整」可勾选显示哪些常用键，长按一行拖动或用上移 / 下移排序，立即生效并只保存在这台手机上；取消勾选的键移到「更多」顶部的「已从快捷键栏隐藏」，仍可使用；「恢复默认」回到上面的顺序。
5. 手机短暂离线、切换主机或重开 App 时，Windows QingCode 继续托管会话。会话 24 小时内既无输入也无输出时由电脑端自动结束（只看手机输入和终端输出，接回查看不算活动），已结束的会话记录同样在 24 小时后清理；会话侧栏每个会话下方显示空闲时长和自动结束时间。更新后的电脑端与 APK 接回时直接显示最新屏幕，再按序号接收后续输出，不再等待旧缓存逐块重放；Server 模式的远端屏幕快照也参与这一流程。

首页显示当前电脑状态、最近项目和最多三个快捷项目入口；离线时可直接重连。首页和项目页在顶部继续下拉即可刷新项目。项目页统一显示本机、WSL 和远端项目，不再使用环境分类；搜索栏吸顶，支持 IP、项目名、连接名及路径，无匹配结果时可一键清除搜索。
终端顶栏右侧可新建终端，顶栏显示当前会话名，项目与来源单行省略、不显示地址。左上角打开会话侧栏，右上角「终端设置」（竖屏为底部弹层，可下滑关闭）可调整并记住手机字号（11–20px），也可在终端输出区双指缩放，缩放时显示当前字号、松手后保存，整个双指手势不发送给终端程序；快捷键 `^C` 直接发送 Ctrl+C，不受已锁定的修饰键影响。回看历史输出时点「回到最新」继续跟随输出。

会话侧栏的「全部」范围按项目分组，顺序固定：切换项目或终端不改变位置，长按组头可拖动项目排序，长按终端行可在所属项目内拖动（原地松手仍是原来的长按操作；搜索、筛选、多选和「运行中优先」时不能拖动），顺序只保存在这台设备上。这台设备打开过或有手机会话的项目会常驻侧栏，关闭全部终端后项目仍在，停留在空项目页。点组头折叠（已记住），组头 `+` 直接在该项目新建终端，`⋯` 可切换到此项目或移除项目。移除只影响这台设备的侧栏，不改动电脑端的项目和文件：确认后关闭其中的手机会话；电脑上开的终端不关闭，项目在它们结束前继续显示。看不到的终端跑完时，行内和折叠的组头显示「有新结果」圆点，看过后清除。切换终端时旧画面保留到新终端写好第一屏，超过约 0.4 秒才显示「正在接入」。

终端底部和首页电脑状态显示「电脑 32 ms」，表示手机到当前电脑的认证请求往返耗时，包括需要时的连接建立，不包含电脑到远端和终端程序处理耗时。终端前台每 10 秒测量，首页等工作台页面每 30 秒测量；切到后台暂停，回到前台立即刷新。同一电脑的终端共用结果，失败、无结果或超过三个采样周期未更新时显示 `--`。连接详情显示测量范围和最近测量时间。旧版电脑不支持时显示 `--` 并提示更新电脑端，不影响其他功能；延迟探测失败不会触发业务重连。
键盘按钮可在实时输入与可编辑命令栏之间切换，空白命令栏点击发送表示回车；组词期间不会提交。切换会话保留各自的未发送草稿。状态行常驻文字「草稿」或「直发」标明当前编辑目标：草稿先在手机编辑、点发送才提交；直发把按键立即发给终端。首次进入终端时在快捷键上方显示一次说明，点「知道了」或主动切换一次模式后不再出现。

在命令输入框上左右拖动可移动光标（类似 iOS 空格键触控板）：草稿模式移动手机草稿光标，直发模式向终端发送 ← / →；竖向拖动仍滚动多行草稿，组词期间不响应。

实时终端中的 http / https 链接可直接点按（含自动折行的长链接），弹出底部菜单「在浏览器打开 / 复制链接」，不会点一下就跳转。`localhost`、`127.0.0.1`、`0.0.0.0` 等电脑本地地址在本机和 WSL 项目中换成当前电脑的局域网地址，并提示开发服务需监听局域网（例如 `--host 0.0.0.0`）、防火墙放行端口；SSH 远端项目的本地地址在远端主机上，只提供复制。全屏程序开启鼠标上报时，「只查看历史」模式按触点识别链接，不向程序发送点击。

输入 Claude / OpenCode 的斜杠命令时，点「/命令」进入实时输入，用 ↑ / ↓ 选择终端候选，Tab 交给当前程序处理，最后点「确认」发送回车。也可先在手机草稿中写 `/effort`：第一次发送只把前缀交给终端，下一次确认才发送回车；更多中的 @引用在光标处插入 @ 并把单行草稿交给终端查看候选。命令和技能列表始终由实际 CLI 提供，不保证每个技能都对应斜杠命令。

输入栏通过占位文字和键盘按钮选中态区分命令编辑与终端实时输入，实时输入时整框使用强调色，不再显示「手机草稿」悬浮标签。上传和发送状态以小图标显示在上方状态行（转圈为进行中、✓ 为已接收、! 为异常，点按可查看），输入框保持完整，不再显示补全提示。✓ 只对本次看着发出的提交显示约 4 秒，随后消失，不常驻勾号，重新进入终端也不回放旧回执；发送中、结果未知和手机保存失败会一直显示。提交原文在「… → 最近提交与项目草稿」查看。按会话记住编辑目标；收起键盘或打开菜单不会自动切回草稿。⌫ 在手机草稿中删除选区或前一个完整字符，在实时输入中发送 Backspace，长按连续退格；松手、切换会话、折叠按键或离开终端立即停止。← / → 同样跟随编辑目标。实时按键不会发送或清空另一份保留的手机草稿，需按键盘按钮主动切回草稿编辑。

「设置 → 发送按键」默认保持文字与回车一起发送、/命令只填入；改为「发送并直接 Enter」后，等待文字送达再间隔 250ms 单独补发回车，/命令也会提交，是否执行由当前程序决定。「更多」提供 @引用、换行、删词、删至行首、清除输入和清空草稿：换行、删词、删至行首跟随编辑目标，本地编辑草稿，远端分别发送 Ctrl+J、Ctrl+W、Ctrl+U。「清除输入」在两种模式均可用，识别到当前 Windows PowerShell 提示行时发送 Ctrl+Home、Ctrl+End，其他程序发送 Ctrl+E、Ctrl+U，保留手机草稿；具体行为由当前程序的按键绑定决定。「清空草稿」只清手机文本，仅在本地模式启用。删至行首与清除当前行都不等于清空全部多行内容。Esc 不承诺删除文字，Ctrl+C 可能中断或退出程序，不能代替清空。中文组词期间快捷删除与提交暂停。

横屏默认收起快捷键，可在状态栏点「展开按键」，手动选择会保存在手机上。接入蓝牙或皮套等实体键盘时也会自动收起；此时手动展开只在本次接入期间有效，拔出键盘后恢复原来的设置。展开后，快捷键占一排，命令栏保持完整宽度；收起不会清除草稿或关闭实时键盘。终端横屏时自动进入 Android [沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)，隐藏系统状态栏和导航栏，保留应用顶栏、状态行及输入栏，不提供手动全屏按钮；转回竖屏或离开终端自动恢复。Android 按系统屏幕方向判断，软键盘缩小 WebView 不会触发方向切换。边缘滑动可暂时唤出系统栏，返回键依次关闭弹层、选区或历史，再返回项目列表。挖孔、圆角和软键盘仍保留必要避让。

在终端输出区单指上下滑动可查看历史输出。Codex、OpenCode 等全屏程序会接管鼠标：默认向上推或往下拉均可进入手机端只读历史，整个手势不会发送给程序，也不会刚打开就回到实时画面；没有更早缓存时会明确提示。进入后按普通页面方式滚动阅读。需要操作程序自身列表时，在「终端设置 → 全屏程序中的触摸」改为「发给程序」。Claude Code 等普通终端的自然滚动保持原有行为；实体鼠标滚轮沿用桌面行为。横向滑动快捷键栏仍用于查看其他按键。

右侧滚动条（普通终端）和变速滑块（开了鼠标的全屏程序）加粗为至少 44px 触控区。按住滑块不动约半秒进入「鼠标模式」，伴随轻震；也可从「… → 鼠标模式」进入。模式显示 72×88px 的悬浮鼠标和独立箭头指针，左右键触控区向外扩展至至少 44px。拖动机身移动指针，点终端只定位指针，不直接点击；点左键才在指针尖端选词或向全屏程序发送鼠标点击。点右键打开菜单：有选区时可「复制」，另有「选中 / 粘贴」，全屏程序多一项「发送右键」，历史面板则是「选中 / 回到最新」。按住左键滑动（不必等长按），或点左键后 0.8 秒内拖动机身，可拖选文字，向请求拖动上报的程序则发送按下、移动和抬起。历史面板里指针同样可用：点按定位、左键选词、拖动选中，选中后在鼠标旁给出「复制 / 取消」；面板是自由滚动的文字，不显示字格高亮。指针按会话记住相对位置，靠近边缘时机身翻转避让。左下角胶囊和强调色滑块常驻；点胶囊、返回键（先关闭选区）、切换会话或离开终端时退出，后台、失焦和旋转时释放按住的鼠标键。

界面动效只加在外壳上，终端内容、光标和手指拖动不做动画：弹层退出、按压缩放、页面与浮层入场、发送回执轻弹、虚拟鼠标从箭头尖端长出、关闭会话时该行原地收起。每次延迟探测成功时，状态圆点和延迟值闪一下，失败不闪。系统开启「减少动画」时全部关闭；WebView 低于 Chrome 117 时弹层退出退化为立即消失。

安卓终端内置 OFL 许可的符号字体子集，补齐 `⏵⏵` 等部分系统字体缺失的状态符号。字体随 APK 离线打包，预加载并在创建 xterm 前等待加载（最多 2.5 秒，失败降级为系统等宽字体）；`unicode-range` 限定符号范围，不替换普通终端文字，也不改写原始输出。

电脑与手机共用后端平滑的程序忙碌状态：Codex、OpenCode 通过 OSC 7501 上报时以上报为准（等待审批算停下，回车提交或收到屏幕快照后作废），其余程序按以下规则判断。标题仍带转圈帧时保持动画，标题恢复普通文字后保留约 3 秒，退出立即停止；不改标题的命令（build、test、日志等）持续输出满约 1 秒也算运行中，停止输出约 3 秒后恢复，输入或改尺寸后 0.5 秒内的回显与重绘不计（输出活跃只影响列表显示与「运行中优先」，后台提醒仍只看标题转圈）；名称与程序标题原样传输，列表刷新和输出轮询按独立版本号合并，避免迟到响应让动画反复启停。旧电脑端没有该字段时，手机仍按当前标题兼容判断。

长按实时终端文字约半秒即可选中，拖动两端手柄可缩小选区或跨行选择；手柄拖至输出区上下边缘时可继续滚动本机已加载的终端缓冲。浮动工具栏提供「复制 / 全选 / 取消」，复制内容写入手机剪贴板，保留中文和换行；「全选」范围为当前 xterm 已加载缓冲。历史分页区域使用系统长按选字和复制。选字不会向 Shell、Claude 或 OpenCode 发送按键和鼠标输入；返回键先取消选区，再处理历史或全屏退出。屏幕旋转、终端网格变化或切换会话时清除旧选区。

终端向历史方向滑动至顶部后，自动衔接只读历史，无需按钮或图标。每次最多加载 120 行，接近当前页顶部时提前请求上一页并保持阅读位置；向最新方向滑回底部即可回到实时画面，也可使用原有「回到最新」或返回键。打开历史时先保留可见终端行，实时输出继续在后台接收。触摸移动逐帧合并，松手后减速滑动，再次触摸立即停止惯性；历史区域使用原生滚动。全屏 TUI 也可通过触摸滑动回看已有历史，实体鼠标滚轮仍交给程序处理，程序本身不追加松手惯性。

电脑端保留普通屏幕滚出的文本历史，并对全屏备用屏被覆盖的画面每秒至多记录一次纯文本，标为「全屏画面历史」。两者共用每个会话 1 MiB / 5000 行上限（先达到的限制生效）；相同画面不重复保存，它不是完整会话录像，也无法读取程序从未显示的内部历史。超出缓存会显示说明，更新前或 Server 断线期间未保留的内容无法补齐。此次全屏历史修复需要同时更新电脑端 QingCode 和 Android APK；旧版电脑端仍按原协议重放。

## 后台提醒

「设置 → 屏幕常亮」默认关闭；开启后停留在应用内时屏幕不自动熄灭，切到后台或手动锁屏后恢复系统息屏设置，不需要额外权限，只保存在这台手机上。

「设置 → 后台提醒」默认关闭；第一次看到程序在运行时会询问一次，也可随时手动更改。开启后，离开应用时若有会话正在运行（或 30 秒内发过输入），手机启动前台服务，每 5 秒向用过的电脑查询一次状态，并在程序停下、发出提醒（BEL、OSC 9 / OSC 777）或会话结束时发通知；点通知直接进入该会话，进入后清除它的通知。

判断依据是电脑端已有的程序忙碌状态，只知道「停下了」，分不清完成和等待审批，文案也不做区分。普通 Shell 命令不设置转圈标题，因此没有运行状态，可在命令后追加 `printf '\a'` 触发提醒。查询只返回会话名、项目名和状态，通知不含终端内容，也不经过任何中转服务器，所以手机必须能连上电脑（局域网或 Tailscale）。

没有会话运行时约 1 分钟后自动停止；连续 10 分钟连不上电脑、或累计留意 6 小时也会停止并通知一次。留意期间持有 CPU 唤醒锁以保证息屏后及时提醒，会增加耗电；可在常驻通知上点「停止留意」结束本次。部分厂商系统可能仍会限制后台，需要把 QingCode 加入电池优化白名单。需要同时更新电脑端和 APK；旧版电脑提示更新，其他功能不受影响。

## 终端渲染

手机终端与桌面一样使用 Unicode 11 字符宽度，emoji 与电脑端屏幕快照对齐。默认使用 WebGL 渲染，全屏程序更流畅；设备不支持时自动使用 DOM 渲染，丢失 GPU 上下文（例如挂起后）时先退回 DOM，回到前台再恢复，同一终端丢失 3 次后不再尝试。画面异常时可在「设置 → 硬件加速渲染」关闭。

第一次接入终端时显示一次「终端手势」说明，关闭后不再出现。

## 配对的保存与撤销

终端底部的「…」菜单在竖屏和横屏沉浸模式下均可用，提供会话列表、新建终端、返回项目列表、展开编辑、提交与草稿、输出阅读。展开编辑适合输入需求、代码和日志；输入法回车只换行，点击「发送」才提交，中文组词期间不会发送，收起继续保留草稿。

手机按电脑和终端分别保存草稿，以及每个终端最近 3 次非空提交的原文；最多保留 24 个终端的编辑记录，提交历史优先于草稿被清理以限制保存量。发送过程显示「正在发送」「电脑已接收」或「提交结果未知」；电脑接收仅表示终端输入写入成功，不代表 Agent 接受、完成任务。结果未知不会自动重发；在「提交与草稿」中查看、复制原文，或追加到当前草稿后手动发送。应用被关闭时仍在发送的记录，下次打开按结果未知处理。电脑端原会话消失后，可在同项目的新终端中手动恢复旧草稿和提交原文；这不会恢复原 Agent 进程。移除电脑会删除该电脑的本地编辑记录，修改连接端口会迁移这些记录。

「终端设置 → 终端列宽」提供适应屏幕、固定 80 列和固定 100 列；固定列宽改变真实终端网格，并允许横向滚动。尺寸变化合并后再调整网格，历史回看在窗口尺寸变化时保留可见文本锚点。

终端顶部显示当前会话名称与所属项目；左上角打开会话侧栏，原顶部横向会话标签移入侧栏。侧栏按项目列出会话，标出当前会话、编号和结束状态；点击会话后自动收起。新建入口置顶，每行右侧可直接关闭，长按或点「⋯」可重命名、置顶与结束；底部集中放置返回工作台、终端设置和关闭全部。关闭其他项不切换当前终端或清空草稿，关闭当前项接回剩余会话。横屏沉浸时顶栏仍在，也可从底部「… → 会话列表」打开同一侧栏；返回键先关闭重命名框，再关闭侧栏。平板（窗口宽至少 840px 且屏幕最短边至少 600px）的终端页支持双栏：默认收起，点左上角侧栏按钮把会话侧栏常驻在左侧，再点一次收起，选择会记在手机上；常驻时切换会话不收起；分屏变窄或横屏手机仍使用可收起的侧栏。

会话名称默认使用终端程序提供的标题（如 Claude / OpenCode），没有标题时显示「终端 N」，通用 Shell / 控制台标题不会覆盖程序名。点会话旁的编辑图标可设置最多 80 个字符的手动名称；手动名称优先，留空保存恢复跟随程序标题。名称由电脑端随手机会话保存，手机断网重连、切换项目后接回会话仍保留；电脑退出后本机和 WSL 的手机会话随之结束；SSH Server 模式的手机终端继续由 daemon 托管，见下方「电脑重启或升级后」。电脑与手机如何互相接入见下方「手机、平板与电脑互相接入」。

会话命名需要同时更新电脑端 QingCode 和 Android APK。旧版电脑仍可使用编号会话和切换功能，重命名入口禁用并显示更新提示。

会话侧栏底部提供「结束全部会话」。确认框显示当前电脑、项目和会话数量；确认后结束该项目列出的全部手机会话（含已结束的记录），关闭 Shell 和前台任务并移除输出。其他项目及桌面终端不受影响。部分失败时保留未确认结束的会话并提示核对，不自动重试。

工作台「终端」首页默认（可在「设置 → 工作台 → 全部会话」关闭）在「继续终端」与「最近打开」之间显示「全部会话」：这台电脑上所有项目的手机会话（包含其他已配对手机创建的会话，标注「来自 设备名」；不含电脑端桌面终端），按项目分组，最近打开的项目在前，每个项目上次接入的会话标「上次使用」。首页先显示 8 个，可「展开全部」；会话不超过 4 个时收起搜索框与筛选，「运行中优先」与「管理」移到标题右侧；搜索（会话名、项目名、来源、设备，多个关键词需全部命中）或按「全部 / 未结束 / 已结束」筛选时显示全部结果。点会话直接打开所在项目并接入；电脑端已移除的项目只能关闭其中的会话。首页可见、App 在前台且电脑在线时每 5 秒刷新，下拉刷新同时更新；没有会话或电脑端不支持时整块隐藏。纵览搜索框右侧与侧栏「新建终端」右侧都有「运行中优先」会话气泡图标：点一下把程序正在工作的会话排到组内最前（置顶会话仍在最上），再点一下恢复电脑端默认顺序，每次点按都有短提示说明当前排序；各处同步，不保存，重开 App 回到默认顺序。会话行的「运行中」转圈与文字默认显示，可在「设置 → 工作台 → 运行状态」关闭（只隐藏显示，排序与后台提醒不受影响）。会话侧栏顶部可在「本项目 / 全部」之间切换（选择保存在手机上），「全部」使用同一纵览，当前项目在前，终端里不必回工作台即可跨项目切换。两处都支持批量管理：点「管理」进入多选，可「全选」（当前筛选与搜索结果）、「选已结束」，再「关闭所选」；确认框统计运行中、已结束、其他设备创建的会话和涉及项目数，逐个结束，失败的保留并提示，不自动重试。单个关闭其他手机的运行中会话时，确认框注明创建设备。关闭其他项目的会话不切换当前终端和草稿。纵览需要电脑端支持 `all_sessions` 能力，旧版电脑隐藏首页区块并禁用侧栏「全部」。

「阅读与搜索输出」提供当前终端缓存和已加载历史的只读快照，最多取末尾 60 万字符；搜索按文字匹配、最多标出 500 处，可上下跳转。阅读时新输出只提示刷新，不替换内容或拉回底部；手动刷新才更新快照。默认不折行，可横向阅读代码与 diff，也可启用自动换行；以 + / - 开头的行提供颜色辅助，网页链接点击后交给系统浏览器，其他文字可选择和复制。搜索范围不包含尚未加载的远端历史，也不等同于完整 Agent 会话记录。

扫码优先请求高清后置摄像头，设备支持时启用连续对焦；预览保留完整画面，识别先保留中央区域细节，再检查全画面。
请将二维码完整放在画面中央，等相机对焦；距离过近时稍微拉远手机。仍无法识别时，可使用「粘贴配对链接」。

- 配对长期有效。Windows 只保存令牌的 SHA-256 摘要，启用状态会被记住：重启电脑端 QingCode 后自动恢复监听，已配对的手机无需重新输入密码。自动启用失败（如端口被占用）时，设置页显示原因。
- 最多同时配对 8 台设备。设置页列出已配对的手机及在线状态，点「移除」即撤销该手机的授权，并结束它创建的终端。
- 「停止连接」关闭监听、结束所有手机终端，并在下次启动时保持关闭；已配对的手机会保留，重新启用后可直接连接。退出 QingCode 同样会结束手机终端，但不改变自动启用设置。
- 从手机移除连接只删除手机上的配对。需要撤销电脑端授权时，在 Windows 设置页移除该设备。
- 默认 TCP 端口为 `48764`，可自定义。密码长期有效，关闭连接或重启电脑端后自动填回，重新启用时留空也可沿用；旧版只保存校验值的密码继续有效，重新设置一次后才可显示。密码与证书私钥一起保存在仅当前用户可读的设置文件中，不会写进二维码或配对链接。更换密码需先停止连接；更换密码不影响已配对的手机。每个来源连续输错 5 次后须等待一分钟，全部来源合计每分钟最多尝试 20 次。

启用后可直接切换端口。新端口成功启用后旧端口停止监听；已配对的手机和正在运行的手机终端都会保留。在手机的「连接详情」中把端口改为新端口即可，无需重新配对，也可以重新扫码。若新端口被占用，原连接继续使用旧端口。Windows 防火墙中手动创建的规则由用户管理。

如果 Windows 防火墙阻止连接，在本机防火墙仅允许所需局域网来源访问所选端口。Windows 须保持在线，WSL 项目须存在对应的发行版，远端项目须能通过桌面已有的 SSH 或 Server 连接打开。打开远端项目时若电脑上弹出确认（如主机指纹），请在电脑上处理，手机最多等待 90 秒。工作区信任控制从哪里启动 Shell，Shell 使用其宿主账号的权限。

手机与电脑之间使用 HTTPS 长连接复用（空闲 10 秒内复用，电脑端 15 秒关闭空闲连接）；读取类请求遇到失效的复用连接会自动重试一次，输入、建终端等写操作不会自动重发。手机创建的终端输出默认只进入移动端缓冲，在电脑标签中打开后才按约 100ms 合并发给桌面窗口。手机终端不进入桌面的遗留终端列表，不能从桌面接回或通过遗留终端操作结束。

### 电脑重启或升级后

SSH Server 模式的手机终端由远端 daemon 托管，电脑退出后进程继续运行，默认连续 24 小时没有接回才回收。电脑重新启动后，第一台拉取会话列表的手机会触发一次后台连接：只连接指纹已确认的 Server 模式可信项目，连不上就跳过，不弹窗；之后每 10 秒扫描一次已连接的 Server，把遗留的手机终端按原会话 id 接回，手机上的草稿仍然对应。接回失败不会结束远端进程。手动名称、终端配置名、最后的程序标题、编号和创建时间由电脑端保存，接回后保持不变；程序发出新标题后照常更新。创建设备不保留，记为第一台拉取列表的手机。本机与 WSL 终端随电脑退出而结束，无法接回；项目被移除或不再信任时也不接回。此行为由电脑端实现，APK 不需要更新。

同一电脑的所有已配对设备共享手机会话，可接入、重命名及结束会话；同一时刻只有一台设备能输入，规则见下一节。不提供设备之间的账号隔离。会话仍记录创建设备；电脑端撤销该设备时结束它创建的会话，并使正在启动的会话失效，迟到的启动结果会触发关闭。

## 手机、平板与电脑互相接入

同一个终端同一时刻只有一台设备在用，手机、平板、电脑规则相同，不按设备型号区分。谁接入，终端就按谁的屏幕显示；程序和进程不受影响。

- 在会话列表、会话抽屉或通知中点选会话视为接管，原设备约 1 秒内显示「已在 X 上接入」和「接回」。断线重连、重开 App 恢复上次界面都不算接管，不会来回互抢。
- 接管不需要对方同意，对方没电或断网时也能立即接回。旧设备迟到的输入和改尺寸会被电脑端按使用权编号拒绝；未更新的 APK 不带编号，只能使用手机会话，且不受独占限制。
- 电脑始终可以只读观看：其他设备使用期间，电脑标签继续显示实时画面并跟随对方的行列，底部提示正在哪台设备上使用，不能输入，点「接回」或「接管」恢复按电脑尺寸显示。
- 手机接入电脑上开的终端需要在「设置 → 功能 → Android 移动连接」勾选「允许手机接入电脑上开的终端」（默认关闭）。「全部会话」会标出「电脑终端」，只列已信任项目的交互式终端，不含运行任务；批量「管理」不勾选这些终端，单个关闭时确认框会说明它是电脑上开的终端。这些终端只出现在「全部」范围，不进入「本项目」和「结束全部会话」。
- 电脑终端的输出由电脑前端在进入渲染批处理之前转发给手机，初始画面取自电脑 xterm 的当前状态并带最多 2000 行历史。手机使用期间电脑窗口需保持运行，最小化不影响转发。移除设备、停止连接或关闭该选项时，电脑上的终端不会结束，只收回使用权。手机长时间未操作也不会自动收回，电脑点「接回」即可。
- 手机创建的终端可在电脑「终端管理」选「在电脑上打开」，默认只读，点「接管」后由电脑操作。关闭这个标签不结束手机上的会话，这类标签不随电脑重启恢复。

需要同时更新电脑端 QingCode 和 APK。旧版电脑端不显示电脑终端，也没有接管提示。

图片读取/上传与终端控制、输出和延迟检测使用不同的有界队列，慢上传不会占住控制线程。请求截止时间包含排队；已超时且尚未开始的输入不再发送，在途网络请求会尝试中止。中止不能证明电脑端撤销了已经接收的操作，所以仍显示结果未知、保留原文，不自动重发。后续成功提交会恢复当前状态，但先前未知的记录仍可查看。系统图片选择器和权限请求等待用户操作，不使用网络请求超时。

移动协议通过认证后的 `capabilities` 只读请求协商版本与功能，旧版电脑不支持该请求时继续沿用原协议。具体约定、自动测试及真机验收矩阵见 [移动端验收](testing.md)。

## 构建 APK

需要 Node 和仓库前端依赖、JDK 17、Android SDK Platform 35 和 Build Tools 35.x。在仓库根目录运行：

```powershell
pnpm.cmd install --frozen-lockfile
pwsh -NoProfile -File scripts/build-android.ps1 -SdkPlatform 'C:\Android\Sdk\platforms\android-35' -BuildTools 'C:\Android\Sdk\build-tools\35.0.1' -Jdk 'C:\Java\jdk-17'
```

设置 `ANDROID_HOME` 和 `JAVA_HOME` 后可省略这三个参数。输出为 `release/QingCode-Android.apk`。

- 版本号取自 `package.json`：`versionName` 与桌面一致，`versionCode` 由 `scripts/android-version.mjs` 推导（`major·10⁷ + minor·10⁵ + patch·10³ + 预发布序号`，正式版排在同号预发布之后），保证升级单调递增。
- 本地构建默认使用 Android 标准调试密钥库 `~/.android/debug.keystore`（不存在时自动生成，与 Android Studio 共用）。同一台电脑上的多次构建可以直接覆盖安装；换一台电脑构建的调试包签名不同，需要卸载后安装。
- 发布构建使用 `-Release` 和固定发布密钥库：`-Keystore`（或 `QINGCODE_ANDROID_KEYSTORE`）、`QINGCODE_ANDROID_KEYSTORE_PASSWORD`、`QINGCODE_ANDROID_KEY_ALIAS`，可选 `QINGCODE_ANDROID_KEY_PASSWORD`。口令通过环境变量传给 `apksigner`。
- Release CI 在配置了仓库 Secrets `ANDROID_KEYSTORE_BASE64`（发布密钥库的 base64）、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`（可选 `ANDROID_KEY_PASSWORD`）时构建 `QingCode_<版本>-android.apk` 并随 Release 发布、同步到 Gitee；未配置时跳过 APK 并给出警告，其余平台照常发布。密钥库一旦用于发布不可更换，否则已安装的手机无法覆盖升级。

系统需为 Android 8.0 或以上，并使用支持当前 xterm.js 的 Android System WebView。扫码需要相机权限，仅在点「扫码添加」时申请。Windows 配套版可用现有 `pnpm package:exe` 流程构建。

## 手机图片与快捷会话

终端顶部「+」、会话抽屉「新建终端」和项目空状态中间的「新建终端」共用同一「新建会话」弹层，选项来自电脑端「设置 → 终端 → 终端配置」，每次打开都会向电脑刷新。手机只拿到配置 id、名称和信任状态；新建会话时电脑端按 id 重新读取命令和 shell，与电脑端新建配置终端走同一条启动路径：本机按配置的 shell 执行，SSH 远端（含远端 Windows 与 Server 模式 daemon）复用 `ssh_spawn_script` 的 interactive 配置终端，WSL 在发行版的交互登录 shell 中执行后保留 shell。带启动命令的配置须先在电脑上选择「信任此配置」，否则手机端提示并不创建。旧版电脑端不支持配置列表时只显示「新建终端」。

终端工具栏的图片按钮直接打开 Android 系统文件选择器，无需申请相册全盘权限，也不再每次询问压缩等级。「设置 → 图片压缩」可选择「原图 · 不压缩」或低 / 中 / 高压缩，自动保存在手机，下次上传直接沿用，默认「中」。低 / 中 / 高压缩的最长边上限分别为 3072 / 2048 / 1280 像素，JPEG 质量分别为 92 / 80 / 60。Android 9+ 使用 ImageDecoder 等比缩小并应用照片方向，Android 8 沿用解码采样与 EXIF 方向；透明图片保留 PNG 格式。

HEIC / HEIF 在手机支持解码时自动转为 JPEG 后上传，包括「原图」选项；PNG / JPEG 原图保留文件字节，其他原图转换时保留分辨率、JPEG 质量 92，为避免内存耗尽拒绝超过 3200 万像素的原图转换，可启用压缩后重试。单张上传最大 8 MB；系统无法解码时提示先转换为 JPEG。

图片上传需要同时更新并重启电脑端 QingCode 和 Android APK。旧版电脑端不识别图片指令或仍限制 128 KB 请求时，会返回「请求格式无效」；手机对此提示更新电脑端。新版电脑端允许已认证请求最多 60 秒传输（配对等未认证请求仍为 15 秒），区分请求过大、读取超时和传输中断，不再全部显示为格式错误。

图片按钮固定在输入框内，快捷键折叠后仍可使用。系统选择器支持一次多选，手机只保留所选图片的引用，逐张读取、上传并把路径插入草稿，显示当前张数；单张仍限制 8 MB。中途失败会保留已插入图片并提示成功张数，重新选择剩余图片即可；切换会话会停止余下图片的上传，释放选择引用，已在传输中的文件不自动撤回或重发。

图片最终统一保存在当前项目 `.qingcode/terminal-paste/<唯一目录>/`：本机项目写入本机仓库，WSL 项目写入发行版仓库并插入 Linux 路径；SSH 项目复用桌面的 SSH / Server 上传流程，写入远端仓库目录。SSH 传输所用的本机临时副本在传输结束后删除；本机和 WSL 不再把 C 盘缓存路径作为最终附件路径。上传前重新核对项目位置和工作区信任，并拒绝附件目录的符号链接逃逸。图片路径进入当前会话的命令草稿，可补充说明后提交。上传不会自动执行回车；取消或切换项目 / 会话后，迟到的结果不会写入其他草稿。超时不自动重发，远端如已收到文件，可按现有终端粘贴清理方式处理。

Android 30+ 由系统栏、刘海和键盘尺寸调整 WebView。终端底部工具区左右各留 8px，快捷键和输入框铺满可用宽度；按屏幕底部圆角与这 8px 边距的交点计算底部净空，扣除系统栏或键盘已避让的高度，只补足剩余间距，不挤窄整块工具区。工作台导航仍以水平内边距避让圆角，内容高 46px、上下各 4px，保留至少 44px 的触摸区域。

## 界面语言

Android 端支持简体中文和英文：默认跟随手机系统语言（中文系统显示中文，其他语言显示英文），也可在「设置 → 语言 / Language」中手动选择，保存在这台手机上并立即重新加载界面，电脑端托管的会话不受影响。文案以中文原文为 key，英文词典位于 `android/web/i18n.js`，同时收录 Android 原生层与电脑端返回的常见错误；新增界面文案时用 `t('中文')` 包裹，`src/lib/mobileAndroidI18n.test.ts` 会检查 JS、`index.html` 与原生错误是否都有英文翻译。
